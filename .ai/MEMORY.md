### Шаг 12: Интеграция Neon с префиксом `tennisapp_` — базы «не было»
- Контекст: у интеграции Neon в Vercel включён **Custom Prefix** `tennisapp_`. В окружение доехали
  только `tennisapp_POSTGRES_PRISMA_URL` и `tennisapp_POSTGRES_URL_NO_SSL` — ни `DATABASE_URL`,
  ни `POSTGRES_URL`; `dbUrlVars` были все `false`, поэтому падали и API, и бот.
- Решение: `dbUrl()` сначала проверяет известные имена (`DATABASE_URL`, `POSTGRES_URL`, `NEON_DATABASE_URL`,
  `DATABASE_URL_UNPOOLED`, `POSTGRES_URL_NON_POOLING`, `POSTGRES_PRISMA_URL`, `POSTGRES_URL_NO_SSL`),
  затем ищет **любую** переменную со значением `postgres://…`, исключая `*PASSWORD*`, `*HOST*`, `*_USER`,
  `*_NO_SSL`, и предпочитает pooled (`-pooler`). `normalizeDbUrl()` убирает prisma-параметры
  (`pgbouncer`, `connect_timeout`, `schema`, …) и добавляет `sslmode=require`. `ping` отдаёт `dbFrom`,
  `health?diag=1` — `dbUrlFrom` и `dbUrlCandidates` (только имена, без значений). `admin/setup` и бот
  проверяют `dbUrl()`, а не конкретное имя.
- Проверка: теневой прогон с `tennisapp_POSTGRES_PRISMA_URL` — строка выбрана и очищена, `ping` →
  `hasDb: true` + `dbFrom`, `health` ok, пароля в ответе нет, `setup` — 18 стейтментов, без токена 401,
  webhook `/start` — 200.

### Шаг 11: Бот молчит — тишина вместо ошибки + секрет webhook
- Контекст: `/api/ping` зелёный, но `hasDb: false`; `/api/bot/setup` вернул `setWebhook: false`
  и `getWebhookInfo.url = ""` (webhook не стоит), `secretConfigured: true`.
- Две причины: (1) бот на ошибке БД слал только `console.error`, а Telegram получал 200 — в чате тишина;
  (2) ручной `setWebhook` без `secret_token` + наша проверка заголовка = 403 на каждый апдейт.
  Плюс `secret_token` с недопустимыми символами Telegram отклоняет, а мы этого не видели.
- Решение: `withDb()` в webhook — админ получает сообщение «Панель временно недоступна: причина + /api/health?diag=1»;
  `/me` вынесен в `meScreen`; `takeLastError()` возвращает текст Bot API (method/status/code/description)
  в `steps[].detail` и в `next`; `secret_token` не отправляется, если пустой; `webhookSecret()` отбрасывает
  секрет не по формату `A-Za-z0-9_-{1,256}` и тогда проверка заголовка отключается (иначе бот молчит);
  `dbUrl()`/`dbUrlPresence()` ищут строку и в `POSTGRES_URL`, `NEON_DATABASE_URL`, `DATABASE_URL_UNPOOLED`,
  `POSTGRES_URL_NON_POOLING`; `health?diag=1` показывает `dbUrlVars` и все имена.
- Проверка: теневой прогон с заглушками Telegram/Neon — `/start` админом без БД даёт сообщение с причиной;
  `setup` с «плохим» секретом → `secretSkipped: true`, webhook ставится; апдейт без заголовка проходит 200;
  с валидным секретом неверный заголовок по-прежнему 403; ошибка Telegram видна в `steps[].detail`.

### Шаг 10: Настоящая причина 500/504 — форма экспорта функций
- Контекст: после PR #9 (чистый tsconfig) сборка перестала ругаться TS2688, но прод отдавал 500 и 504.
  Значит транспиляция проходила, ломался сам вызов.
- Причина: все функции экспортировали «голую» функцию `export default async function handler(request)`.
  Node-рантайм Vercel вызывает такой default как `(req, res)` из http: `Response` никуда не отправлялся,
  запрос висел до таймаута (504), а необработанный rejected promise ронял инвокацию (500).
  Web-сигнатура в Node-рантайме поддерживается только у объекта с методом `fetch`.
- Решение: все 9 функций `api/**` → `export default { fetch: handler }`; `health` показывает флаг пароля
  и по `SETUP_TOKEN`, и по `ADMIN_SETUP_TOKEN`. В `smoke.mjs` добавлена регрессия: голый default-экспорт
  в `api/**` валит смоук.
- Проверка: `tsc` оба конфига; теневой прогон `fetch`-экспортов с заглушкой Neon — `ping` 200,
  `setup` 200/`applied: 18`, без токена 401, `health?diag=1` 200; `build` и `smoke` зелёные.
- Урок: в Node-рантайме Vercel не использовать голый default-экспорт; писать `{ fetch }`,
  именованные `GET`/`POST` или один роутер в `api/index.ts`.

### Шаг 9: Причина 500 — tsconfig ломал транспиляцию функций
- Контекст: все `/api/*` отдавали `FUNCTION_INVOCATION_FAILED` уже после фикса импортов.
  Лог сборки Vercel показал `error TS2688: Cannot find type definition file for 'node'`
  и `'vite/client'` на каждой функции, а также `[db-setup] DATABASE_URL не задан`.
- Решение: из корневого `tsconfig` убраны `types` (vite/client подключён через
  `src/vite-env.d.ts`), добавлены самостоятельные конфиги `api/tsconfig.json` и
  `tsconfig.api.json` без `types` + мини-декларации `api/**/neon.d.ts`, `node-shim.d.ts`
  (Response/fetch/crypto берутся из lib DOM). Накатка схемы перенесена из build-скрипта
  в функцию `api/admin/setup.ts` (`sql.query` с текстом, 18 идемпотентных стейтментов),
  скрипт `scripts/db-setup.mjs` удалён. Добавлен `api/ping.ts` — проверка рантайма без

- Альтернативы: оставить `types` и надеяться, что Vercel установит типы в песочнице —
  не работает; `ignoreBuildErrors` для функций — Vercel такого не даёт.
- Риски: мини-декларации частично описывают API Neon (`query`, тег-шаблон) — при переходе

### Шаг 8: Импорты `.js` — настоящая причина 500 в функциях
- Контекст: после перехода на `.ts`-расширения функции всё равно падали на Vercel
  (`FUNCTION_INVOCATION_FAILED`) до выполнения кода. Владелец не может запускать curl
  (VPN только в браузере), `SETUP_TOKEN` в Vercel не совпадал.
- Решение: Vercel компилирует `.ts` → `.js`, но **не переписывает пути импорта**, поэтому
  `'./_lib/db.ts'` в скомпилированном файле указывает на несуществующий `.ts`. Перешли на
  стандарт NodeNext — в исходниках пишем `'./_lib/db.js'` (все `api/**`, включая `bot/`).
  `api/bot/setup.ts`: доступ по `SETUP_TOKEN`, по `initData` админа или (если токен не задан)
  открыт — эндпоинт лишь переставляет webhook на собственный адрес, поле `access` объясняет
  причину. `health?diag=1` отдаёт ещё и коммит сборки.
- Альтернативы: убрать `"type": "module"` — тянет переименование vite.config в `.mts` и даёт
  warning-и; `.ts`-расширения с `allowImportingTsExtensions` — работают в tsc, но не в рантайме
  (проверено: модуль не грузится).
- Риски: в исходниках видно `.js` при файлах `.ts` — это норма ESM+TS, но удивляет; при
  добавлении новых файлов в `api/` писать только `.js` в относительных импортах.
- Проверка: компиляция «как Vercel» (`tsc` NodeNext в чистую папку) — 0 ошибок, затем все
  7 функций загружаются через `import()`; до фикса тот же тест давал `ERR_MODULE_NOT_FOUND`.
  Webhook отдаёт 200 при недоступной БД; setup проверен на 5 сценариях доступа.

- Проверка: прогон webhook с заглушками Telegram API и БД — 13 SQL, все экраны
  отрисованы, отмена работает, чужие получают отказ, без секрета 403, GET 405;
  все модули бота грузятся как ESM; `typecheck`/`build`/`smoke` зелёные.

### Шаг 5: Фикс 500 на Vercel и отступов в мобильном виде
- Контекст: `/api/health` отдавал `FUNCTION_INVOCATION_FAILED` на проде, все ручки падали,
  приложение уходило в демо-режим. Плюс замечание: плашки и ленты заходят на край экрана.
- Решение: в `api/**` относительные импорты получили явное расширение `./db.ts` —
  `package.json` с `type: module`, и ESM-резолвер Node не находил модуль без расширения
  (`ERR_MODULE_NOT_FOUND` до вызова функции, отсюда 500). Отступы: `.scroller` больше не
  тянет контент за край (убран `margin-inline: -gutter`), выезд вынесен в модификатор
  `.scroller--bleed`, добавлен `.scroller--flat`; у `.coach-strip` остался один выезд вместо двух.
- Альтернативы: убрать `type: module` — сломало бы Vite-конфиг и `server/preview-api.ts`;
  править отступы отрицательными margin в местах использования — разъезжается при правках.
- Риски: `scroller--bleed` используется в двух местах (дни, тренеры) — при добавлении новых
  лент выбирать модификатор осознанно.
- Проверка: функция загружается как ESM (ошибка теперь только `fetch failed` без сети к Neon),
  `isAdmin()` по ID `793536041` = true, `readNumber` отдаёт 400, `typecheck`/`build`/`smoke` 7/7.

### Шаг 4: Деплой в main, схема через сборку Vercel
- Контекст: PR #1 смержен; деплой Vercel падал, GitHub Actions `db` не видел секрет
  `DATABASE_URL` (ни Secret, ни Variable не пробрасывались), сеть к Neon из песочницы закрыта.
- Решение: из `vercel.json` убран неподдерживаемый `functions.runtime` (только
  `maxDuration`), добавлен `engines.node=22.x` — деплой стал зелёным. Наполнение базы
  перенесено в сборку: `scripts/db-setup.mjs` в `npm run build` применяет идемпотентные
  schema+seed, где `DATABASE_URL` Vercel точно доступен; без переменной шаг пропускается.
- Альтернативы: чинить секрет в Actions — доступ к настройкам секретов у токена закрыт,
  владелец должен сделать руками; psql/`pg` из песочницы — TLS к Neon обрывается.
- Риски: DDL на каждой сборке; спасает идемпотентность (`if not exists`, `on conflict`).
  Если база недоступна, скрипт логирует ошибку и не валит сборку — сайт выйдет на демо-данных.
- Проверка: Vercel status `success`; локально `npm run build` пропускает шаг без
  `DATABASE_URL`; `smoke` 7/7; `typecheck` чист.

### Шаг 3: Координаты проекта и роль администратора
- Контекст: владелец подключил Neon через Vercel, задал `TELEGRAM_BOT_TOKEN`, дал бота

- Решение: `ADMIN_BOT_URL`/`CLUB_BOT_NAME`/`APP_URL` читают `VITE_*` с рабочими значениями;

- Альтернативы: применять SQL из песочницы — невозможно (SSL/HTTP к Neon закрыт);
  локальный pg-клиент даёт «Connection terminated».
- Риски: `ADMIN_TELEGRAM_IDS` пока пуст — вход в админку по username `nikita_tsk`;
  username можно сменить, поэтому нужен числовой ID.
- Проверка: `typecheck`, `build`, `smoke` (7/7 после переноса фикстуры на завтра), dev-сервер

### Шаг 2: Vercel + Neon + вход из Telegram
- Контекст: владелец выбрал связку Vercel + Neon; мини-апп открывает сайт из Telegram Apps.
  Требовалось также дать посмотреть сайт локально без установки.
- Решение: API как серверные функции Vercel (`api/*.ts`) на `@neondatabase/serverless`
  (HTTP, без пула); `initData` проверяется HMAC-SHA256 в `api/_lib/telegram.ts`;
  схема и сид — `db/*.sql`, применение — GitHub Actions. Фронт переведён на `/api` с
  автоматическим откатом в демо-режим (`lib/store.ts`), каталог — `lib/useCatalog.ts`
  поверх демо-данных, чтобы экран не пустовал. Локально `/api/*` эмулирует Vite-плагин
  `server/preview-api.ts` (файловая «база» в `.preview/`, в git не попадает).
- Альтернативы: единственный режим «только API» — отклонено: без переменных окружения сайт
  не откроется; Next.js — лишний вес для одной статики и четырёх функций; Prisma — не
  нужна, `neon()` даёт параметризованные теги-шаблоны без ORM.
- Риски: SQL и HMAC не прогонялись на реальной Neon (нет секретов) — первый прогон на
  Vercel; вывод `rating` приведён к float, иначе numeric приходит строкой.
- Проверка: `npm run typecheck`, `npm run build`, `npm run smoke` (каталог из `/api`),
  curl: `/api/health` 200, повторная бронь окна и переполненное занятие → 409, отмена
  возвращает окно в продажу, заказ создаётся.

### Шаг 1: Мини-апп клуба ДТ — первый рабочий прототип
