# 🚀 Деплой: Vercel + Neon + Telegram

Схема работы: Telegram открывает Mini App внутри своего клиента; приложение и API
размещены на Vercel, данные — в Neon. Локальный предпросмотр — ниже.

```text
Telegram (меню бота / inline-кнопка web_app в личном чате)
        │  открывает HTTPS-адрес Mini App внутри Telegram
        ▼
Vercel: статика (dist) + функции /api/*
        │  @neondatabase/serverless (HTTP, без пула)
        ▼
Neon: users · courts · coaches · training_sessions · free_slots · bookings · products · orders
```

## 1. Посмотреть сайт здесь, без установки

Запустите `npm run dev` для локального предпросмотра.
Vercel и Neon для этого не нужны: `server/preview-api.ts` поднимает те же маршруты
`/api/*`, данные — из `src/data/club.ts`, запись — в `.preview/db.json` (в git не попадает).

```bash
npm run dev     # http://localhost:5173 — сайт + эмулятор API
npm run build   # типы + production-сборка
npm run smoke   # рендер собранного бандла в jsdom + проверка /api
```

Проверить API руками:

```bash
curl -s localhost:5173/api/health     # {"mode":"preview","ok":true}
curl -s localhost:5173/api/catalog    # корты, тренеры, занятия, окна, товары
```

Демо-данные доступны только в локальном `npm run dev`. В production при ошибке
загрузки каталога или личных данных показывается ошибка с повторной попыткой,
а не демо-расписание или пустой список. `npm run preview` обслуживает production-сборку
без локального API и без обхода Telegram-входа.

## 2. Neon

1. Neon подключён к Vercel через интеграцию. **Внимание на префикс:** если в
   Installation → Settings задан Custom Prefix (у нас был `tennisapp_`), переменные
   называются `tennisapp_DATABASE_URL`, `tennisapp_POSTGRES_PRISMA_URL` и т.п.
   Код это учитывает: `dbUrl()` в `api/_lib/db.ts` сначала смотрит известные имена,
   затем любую переменную со значением `postgres://…`, предпочитая pooled-строку,
   и вычищает prisma-параметры (`pgbouncer`, `connect_timeout`), добавляя `sslmode=require`.
   Проверить, что именно найдено: `GET /api/ping` → поле `dbFrom`.
2. **Только для новой/тестовой базы:** `/api/admin/setup` применяет схему **и демо-данные**.
   На рабочей базе не запускайте его без резервной копии и согласованного плана:
   демо-наполнение может добавить записи и сдвинуть `starts_at`.
3. Для состояния админ-бота на существующей базе сначала сделайте и проверьте
   резервную копию и убедитесь, что выбрана именно рабочая база. Затем выберите
   **один** из способов применить только `public.bot_dialog_state` без `SEED`:

   - До деплоя выполнить в Neon SQL Editor файл `migrations/001_bot_dialog_state.sql`.
     Так таблица будет готова до переключения бота на новый код.
   - Либо после деплоя вызвать защищённый эндпоинт (до вызова админская панель
     сообщит об отсутствии таблицы; пользовательское меню при этом доступно):

     ```
     https://mini-seven-xi.vercel.app/api/admin/migrate-bot-state?token=<ТОКЕН>
     ```

   Если в Vercel задан `ADMIN_SETUP_TOKEN`, подставьте его; только если переменная
   отсутствует — `SETUP_TOKEN`. Заданный пустой `ADMIN_SETUP_TOKEN` закроет доступ.
   Не публикуйте ссылку с токеном. Оба способа создают только новую таблицу,
   не меняя занятия, окна, брони или заказы; в этой подготовке они не выполнялись.
4. При изменении `db/*.sql` или `.github/workflows/db.yml` в `main` workflow `db`
   может автоматически применить **всю** `db/schema.sql` к базе из GitHub Actions;
   при push он не запускает `db/seed.sql`. Ручной workflow с seed и команда
   `psql ... -f db/seed.sql` подходят лишь для новой/тестовой базы.
   Таблица `bot_dialog_state` намеренно не добавлена в `db/schema.sql`, чтобы этот
   PR не запускал workflow при merge; она описана в `api/_lib/schema.ts` и
   `migrations/001_bot_dialog_state.sql`. После создания новой базы из `db/schema.sql` тоже нужно
   отдельно применить миграцию состояния бота.
5. Проверка: `https://<проект>.vercel.app/api/ping` → `{"ok":true,...}`,
   затем `/api/health?diag=1` → `ok: true` и данные Neon.

Брони и заказы связаны с `users.telegram_id`. **Блокер перед безопасной выкладкой:**
исторические гостевые ID могли пересекаться с настоящими Telegram ID. При совпадении
пользователь может увидеть старые данные гостя. По одним ID надёжно различить эти
случаи нельзя; код их не удаляет и не разделяет. Нужны резервная копия, отдельный
согласованный аудит и план устранения коллизий до выпуска для игроков.
Для первичной оценки можно после backup выполнить **только чтение** (результат —
счётчики, без имён и телефонов):

```sql
select
  count(*) as ids_in_legacy_guest_range,
  count(*) filter (where u.first_name = 'Гость с сайта') as still_named_guest,
  count(*) filter (where exists (select 1 from bookings b where b.user_id = u.id)
                       or exists (select 1 from orders o where o.user_id = u.id)) as with_bookings_or_orders
from users u
where u.telegram_id between 900000000 and 999999999;
```

В этом диапазоне могут быть и реальные Telegram-аккаунты; имя гостя могло быть
изменено при заказе. Ненулевой счётчик не доказывает коллизию, а отсутствие имени
«Гость с сайта» не доказывает её отсутствие. Не удаляйте строки и не переносите
записи автоматически по результату этого запроса.

Существующие `/api/client` и `/api/orders` при холодном старте также выполняют
`CUSTOMER_SCHEMA`: создание недостающих полей/последовательности и заполнение
отсутствующих номеров клиентов. Этот PR не добавляет эти операции, но перед
выкладкой и проверками на рабочей базе тоже нужна резервная копия.

## 4. Telegram

1. **@BotFather → /newapp** (или /setmenubutton): укажите URL
   `https://<проект>.vercel.app`.
2. Новые кнопки в боте открывают Mini App через `web_app` в **личном чате**.
   Для кнопки меню Telegram и списков команд используйте защищённый
   `/api/bot/setup?mode=menu&token=<SETUP_TOKEN>` — он не меняет webhook и не сбрасывает очередь.
   Кнопки в старых сообщениях не изменятся: отправьте боту `/start` заново.
   Укажите верный HTTPS `VITE_APP_URL` без query/fragment; если он отсутствует,
   используется `https://mini-seven-xi.vercel.app`.
3. Официальный SDK передаёт сырой `Telegram.WebApp.initData` в `POST /api/me`
   через `Authorization: tma <initData>`. Сервер проверяет HMAC-SHA256 по
   `WebAppData` и токену бота, пользователя и возраст `auth_date` (до 10 минут).
   `initDataUnsafe` не используется для авторизации или имени на экране.
4. После проверки сервер выдаёт сессию на **2 часа**, привязанную к origin;
   клиент держит её только в памяти и передаёт как `Authorization: tma-session …`.
   После окончания сессии или ответа 401 приложение предлагает закрыть его и
   открыть заново из бота. Сессия не продлевается сама собой. Не сохраняйте и
   не публикуйте `initData`, сессионный токен или заголовки запросов.
5. Без проверенной подписи или сессии `/api/client`, `/api/bookings`, `/api/orders`
   и `/api/me` не отдают личные данные. Открытый `/api/catalog` содержит только
   справочник. В обычном браузере production и Vercel Preview показывают
   инструкцию, но не интерфейс приложения. Только `npm run dev` включает отдельный
   локальный эмулятор без Telegram.

**Важно:** HTTPS-адрес всё равно нужен Telegram для загрузки приложения, но кнопка
в боте должна быть `web_app`, не `url`. Inline-кнопка в личном чате и меню бота
передают данные пользователя; обычная ссылка на сайт и запуск с reply-клавиатуры
не дают нужного `initData`. Для проверки используйте новую кнопку после `/start`.
Контакт «Написать в клуб» ведёт в чат бота, а не на сайт приложения.
Для live-проверки Preview используйте отдельного тестового бота, тестовую базу и
его HTTPS-домен: настройка меню или webhook рабочего бота меняет его для всех.

Сессия — bearer-токен: её кража позволяет повторно использовать её до истечения
срока. Индивидуального отзыва или одноразового обмена нет; смена токена бота
аннулирует все такие сессии. Это ограничение требует дальнейшей работы, если
понадобится немедленный отзыв или более строгая защита от повторного использования.

## 5.1. Telegram-бот: роли, команды и настройка

Бот `@testtesttennisbot` работает только в личных чатах. Код: `api/bot/webhook.ts`,
пользовательские экраны — `api/bot/_lib/user-screens.ts`, админские — `screens.ts`.

| Роль | Что доступно |
| --- | --- |
| Администратор: ID из `ADMIN_TELEGRAM_IDS` | `/start` и `/admin` открывают панель: записи, расписание, окна, заказы, товары, игроки и журнал; `/me` — свои записи, «👤 Вид игрока» — просмотр пользовательского меню. |
| Игрок: любой другой Telegram ID | `/start`, `/me`, `/orders` (свои заказы), `/schedule` (просмотр по дням), `/help`, «О клубе», открытие Mini App и отмена своей будущей записи с подтверждением. Запись, аренда и оформление заказа — в Mini App. |

Роль проверяется на сервере для каждого сообщения и callback после проверки секрета webhook.
В группах бот не показывает личные данные и панель. Отмена чужой записи отклоняется;
при аренде нескольких окон каждое отменяется отдельно. В боте показываются до 12
ближайших записей и до 10 последних заказов.

В расписании администратора «＋ ресепшен» создаёт телефонную запись, «− ресепшен»
снимает только её, не затрагивая бронь игрока. Старые ручные изменения счётчика без
записи не корректируются этими кнопками — для них нужен отдельный аудит. Окно,
занятое игроком, нельзя вернуть в продажу без отмены записи. Число мест нельзя
уменьшить ниже занятых, а время занятия с записями — поменять: сначала нужно
согласовать и отменить записи. Посещение отмечается после начала занятия.

`ADMIN_TELEGRAM_IDS` — числовые ID через запятую, например `793536041,123456789`.
Если переменная отсутствует, действует ID владельца `793536041`; пустое значение
не даёт прав никому. **Доступ по username больше не работает**: до деплоя добавьте
ID каждого администратора в Vercel. Поле `users.role` — метка в карточке, а не право
входа в панель. Setup создаёт отдельные списки команд для указанных ID; старые chat
scopes могут сохраниться после удаления ID, но сервер всё равно отклонит действия.

**Первичная настройка** (только при включении webhook или изменении его секрета):
в Vercel задайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `SETUP_TOKEN`,
`ADMIN_TELEGRAM_IDS` и `VITE_APP_URL`, затем вызовите защищённый
`/api/bot/setup?token=<SETUP_TOKEN>`. Полный setup использует
`drop_pending_updates: true` и **сбросит ожидающие обновления**.

**Только обновление меню** после деплоя, смены URL или списка админов:

```
https://mini-seven-xi.vercel.app/api/bot/setup?mode=menu&token=<SETUP_TOKEN>
```

Эта команда не переустанавливает webhook и не сбрасывает ожидающие обновления.
Проверьте `ok: true` и каждый элемент `steps`; ошибки Telegram выводятся там же.
Если настройка chat scope не удалась, администратор должен сначала написать `/start`
боту в личном чате. Не отправляйте токены и ссылки с ними в чат.

Для диагностики используйте `/api/health?diag=1`, затем проверьте `/start` с
администраторского и обычного аккаунтов, меню, Mini App и собственные записи.

**Надёжность.** Webhook проверяет `X-Telegram-Bot-Api-Secret-Token`; ответ Telegram
всегда 200, ошибки ловятся и логируются, чтобы апдейт не ретраился бесконечно.

> ⚠️ Если секрет webhook не задан или не совпадает, запросы к webhook отклоняются с 403.

### Важно: существующие даты и подготовка базы

До исправления процедуры наполнения не запускайте `/api/admin/setup` на рабочей базе
без резервной копии и проверки: старый `SEED` пересчитывает `starts_at` по `day_offset`
и может перенести существующие занятия и окна. Кнопка «Починить схему» отключена.
Для новой таблицы состояния бота используйте `/api/admin/migrate-bot-state?token=...`
после резервной копии — этот эндпоинт не содержит `SEED`.
